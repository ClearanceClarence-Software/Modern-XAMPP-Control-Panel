Every feature, in plain words.

Nothing here needs a config file opened by hand. Each one is a button in the panel.

[the panel]9 features

The panel

The window you already know how to use, with the rough edges taken off.

Familiar layout

Module rows for Apache, MySQL, FileZilla, Mercury, Tomcat and Mailpit with Service, PID(s), Port(s), Start/Stop, Admin, Config and Logs, plus Config, Netstat, Versions, Databases, Logs, Sites, PHP, Shell, Explorer, Services, Help and About buttons.

Your language

English and Norwegian Bokmål are built in; Config › Language switches at once. Adding a language is one JSON file, see docs/translating.md.

Light and dark themes

Follows Windows by default; the sun/moon button in the header switches.

Tray icon

Shows what runs, starts and stops modules from its menu, keeps the panel out of the taskbar when minimized.

One admin prompt per session

Service actions and the hosts file reuse a single elevation.

Start all and Stop all

In the header of the module list and in the tray menu. Start all starts the modules ticked as Autostart, or Apache and MySQL when none is.

Quit asks

Closing with Apache or MySQL running offers a clean stop or leaving them running.

Updates itself

The header shows when a newer version exists; What's new lists every release since yours and installs the newest with one click (signed zip, checksum verified, the exe swapped on restart).

Crash reports

An unrecoverable error shows a window with the details and a button to open an issue; the report is also saved to crash.log.

[safe servers]5 features

Safe servers

Starting and stopping without damage, and a reason whenever something refuses.

Clean MySQL/MariaDB shutdown

Stop always tries mariadb-admin shutdown first. A hard kill is only offered as Force stop when that fails, and it tells you InnoDB will run crash recovery.

Startup failures explained

httpd -t runs before Apache starts and names the broken line. If Apache or MySQL exits right after starting, the last lines of error.log or mysql_error.log appear in the panel.

Port conflicts found and fixed

Before a module starts, the panel names the program and PID holding each port. A dialog offers to end that program, stop IIS when Windows itself holds the port, or move Apache to 8080/4433 (MySQL to 3307) with the config files and settings updated.

Netstat

Every program that listens on a port, one entry each, with what its ports are for (Apache, MySQL, HTTP, Remote Desktop…), who can reach it, and a warning when a foreign program blocks a stopped module. Select one for its details and to open it in the browser, show its folder, copy, or end it. Search, or narrow to XAMPP's programs or the blocking ones.

Logs window

Every server log in one side list, each with a count of its recent errors. The chosen log is followed live, like tail -f, with each line split into time, level and message, a filter, a "Problems" switch, and a timeline that shows when things went wrong and jumps there.

[development tools]5 features

Development tools

The jobs that used to mean editing config files by hand.

Sites with HTTPS

Give each project its own address, such as https://myproject.test. Apply writes the virtual hosts to a marked block in httpd-vhosts.conf, tests the config, adds the names to the hosts file, issues a certificate from a local authority Windows trusts, and restarts Apache. localhost keeps serving htdocs. Each site has Editor and Terminal buttons.

PHP settings

The values everyone changes (memory limit, upload size, time limits, display errors, time zone) and every extension in php\ext with a check box. The previous file is kept as php.ini.bak.

Xdebug with one button

Installs the build that matches your PHP (version, thread safety, compiler) from PECL, turns it on in debug mode on port 9003, and off again when you want speed.

Mail catcher

Installs Mailpit and points mail() at it. Every message shows at http://localhost:8025 instead of leaving your computer.

Databases

A searchable list with sizes, and the chosen database beside it: tables, collation and its last export. Export to a timestamped .sql (routines, events and triggers included), import into a new or existing database, open it in phpMyAdmin, drop.

[versions]4 features

Versions

Newer PHP and MariaDB than XAMPP ships, kept side by side.

PHP and MariaDB

Install a new version straight from windows.php.net or downloads.mariadb.org (SHA-256 verified) or from a zip, switch between installed versions in seconds, switch back after any install or switch, remove what you no longer need.

Updates are announced

At startup and once a day the panel looks for newer builds of the PHP, MariaDB, Mailpit and Xdebug you have installed. A count on the Versions button and an arrow on the module's row say so; "Update to 8.5.13" on the active row installs it, and the panel then asks whether to remove the build it replaced. A whole new PHP branch is mentioned once, not nagged about.

FileZilla Server

XAMPP still ships FileZilla Server 0.9.41 from 2012. The Versions window runs the official 1.x installer you downloaded and the FileZilla row then controls the new server. (1.x can't read 0.9's settings, so FTP users are set up again in its Admin program.)

XAMPP-style configuration

Editor, browser, XAMPP folder, autostart per module, start minimized, minimize to tray, update check, port check on startup, debug output, two-tone or plain icons, Service and Port Settings, User Defined Files and Log Options.
