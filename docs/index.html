How versions work

The active build always lives where XAMPP expects it (C:\xampp\php and C:\xampp\mysql), so Apache's config and my.ini keep working. Other builds are kept in C:\xampp\versions\php\<version> and C:\xampp\versions\mariadb\<version>, and switching swaps the folders.

PHP. Only PHP 8 Thread Safe x64 builds are supported, because XAMPP runs PHP as an Apache module. A new version carries over your php.ini, PEAR and XAMPP's extras. Extensions the new build doesn't include are commented out in php.ini and listed in the log. On every install or switch, the DLLs PHP shares with Apache (OpenSSL, libssh2, nghttp2, …) are synced, using the newer copy of each, so php_curl and mod_ssl both load.

MariaDB. Each version keeps its own databases. They can't share one data folder: a newer server converts the data files so older servers can't open them. Installing a newer version:

  1. optionally saves an SQL dump of all databases to C:\xampp\mysql_dumps,
  2. does a full clean shutdown (innodb_fast_shutdown=0),
  3. copies the data folder, my.ini, scripts and batch files into the new version,
  4. starts it and runs mariadb-upgrade, repairing Aria system tables if needed.

The previous version stays installed with its own untouched copy, so switching back gives you the exact state from before the update. Downgrades are refused.

Settings and files

What Where
Settings %AppData%\XamppControl\settings.json
Optional log file %AppData%\XamppControl\xampp-control.log
Crash reports %AppData%\XamppControl\crash.log
Local certificate authority %AppData%\XamppControl\local-ca.pfx (private) and local-ca.crt (public)
Site certificate C:\xampp\apache\conf\ssl.crt\modern-xampp-local.crt and ssl.key\modern-xampp-local.key
Downloads %TEMP%\XamppControl
Installed versions C:\xampp\versions\
SQL dumps C:\xampp\mysql_dumps\
Mailpit C:\xampp\mailpit\ (exe, mailpit.db, mailpit.log)

The local certificate authority's private key (local-ca.pfx) can sign certificates your browser trusts, the same way mkcert works. It never leaves your computer, but keep it private, and remove "Modern XAMPP Control Panel Local CA" from Windows' certificate manager (certmgr.msc, Trusted Root Certification Authorities) if you stop using the panel.

The MySQL root password (Config › Service and Port Settings) is only used for clean shutdowns, dumps, the Databases window and upgrades. It is stored in plain text in settings.json, which is fine for a local development machine but worth knowing.

Troubleshooting

Coming from the stock panel with a database that won't start? See XAMPP: "Error: MySQL shutdown unexpectedly" for the fix, step by step.

MySQL won't stop cleanly Set the root password under Config › Service and Port Settings. If the server really is stuck, use Force stop.
A module runs as a Windows service Updates and version switches need the module to run normally. Untick its Service checkbox first (this asks for admin rights).
A site shows "Not secure" Click Trust in the Sites window and answer Yes to Windows' warning. Firefox keeps its own certificate list: import local-ca.crt there, or set security.enterprise_roots.enabled to true in about:config.
A site name doesn't resolve The hosts file is only changed after the admin prompt. If you canceled it, or an antivirus blocked the change, click Apply again.
Apache won't start after a PHP change The panel shows the reason from error.log. Use Switch back in the Versions window to return to the previous PHP.
Xdebug install says PECL has no build PECL builds each Xdebug release per PHP branch and compiler; a brand-new PHP may have to wait a release. Try again after the next Xdebug version, or install an older PHP branch from the Versions window.
Mail from PHP still doesn't show in Mailpit Check that the Mailpit row is running and that php.ini has sendmail_path pointing at mailpit.exe sendmail (the install sets it; Apache must restart afterwards). Code that uses its own SMTP settings (PHPMailer, Laravel) should point at 127.0.0.1:1025.

Building from source

Requirements: the .NET 10 SDK.

git clone https://github.com/ClearanceClarence-Software/Modern-XAMPP-Control-Panel.git
cd Modern-XAMPP-Control-Panel
dotnet run --project XamppControl.csproj

Self-contained single-file build, as published in releases:

dotnet publish XamppControl.csproj -p:PublishProfile=win-x64
# bin\publish\win-x64\XamppControl.exe

Releases are built, signed with a Certum code-signing certificate and uploaded as a draft on the maintainer's PC with tools/release.ps1; GitHub Actions checks that each push formats, builds and passes the tests. See docs/code-signing.md and docs/testing.md.
